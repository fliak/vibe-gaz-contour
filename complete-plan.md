# Техническое задание

## Демонстрационная PWA для просмотра телеметрии и документов ШРП/ГРП

**Версия:** 1.0  
**Статус:** проект ТЗ  
**Целевая площадка:** `https://medvedzol.soil.by`

---

## 1. Назначение

Разработать демонстрационное мобильное web-приложение в формате PWA, показывающее концепцию голосового помощника для работы с объектами ШРП, ГРП и ГРПШ.

Приложение должно:

- выглядеть и работать как мобильное приложение на Android;
- открываться обычной ссылкой в браузере;
- устанавливаться на главный экран из Google Chrome;
- показывать настроенные вручную объекты и их текущие показатели;
- открывать схему и режимную карту объекта;
- демонстрировать голосовой и текстовый поиск;
- работать без backend и без подключения к реальной телеметрии.

Приложение не предназначено для промышленной эксплуатации, диспетчеризации или гарантированной доставки аварийных сообщений. Все данные являются демонстрационными и изменяются вручную в конфигурационных файлах.

---

## 2. Формат решения

Решение представляет собой статическое одностраничное приложение (SPA/PWA), размещённое за nginx.

### 2.1. Рекомендуемые технологии

- React;
- TypeScript;
- Vite;
- HTML/CSS;
- Web App Manifest;
- Service Worker;
- Web Speech API для экспериментального распознавания и озвучивания речи;
- JSON для конфигурации объектов.

Backend, база данных и постоянно работающий Docker-контейнер для демонстрационной версии не требуются. Docker допускается использовать только для воспроизводимой сборки приложения.

### 2.2. Целевые устройства

Основной сценарий проверки:

- смартфон Android;
- актуальная версия Google Chrome;
- вертикальная ориентация экрана;
- доступ к интернету для первоначальной загрузки и распознавания речи.

На компьютере приложение должно оставаться работоспособным и отображаться в адаптивной мобильной или расширенной компоновке.

### 2.3. Размещение

Рабочий адрес приложения:

`https://medvedzol.soil.by`

Для установки PWA, работы Service Worker и доступа к микрофону сайт должен обслуживаться по HTTPS. Сертификат может быть выпущен бесплатно через Let's Encrypt.

## 3. Границы демонстрационной версии

### 3.1. Входящие функции

- каталог объектов из JSON-конфигурации;
- ручные значения телеметрии из JSON;
- выбор текущего объекта;
- три основных раздела: «Голос», «Телеметрия», «Документы»;
- отображение статуса и времени обновления данных;
- просмотр изображений и PDF;
- ссылки на схему и режимную карту объекта;
- ограниченный голосовой поиск;
- текстовый поиск как гарантированный fallback;
- кнопки с заранее подготовленными демонстрационными вопросами;
- озвучивание найденного ответа, если синтез речи поддерживается браузером;
- базовая офлайн-работа с ранее загруженной оболочкой, конфигурацией и открытыми документами;
- установка PWA на главный экран.

### 3.2. Не входящие функции

- подключение к реальным датчикам, контроллерам или SCADA;
- автоматическое обновление телеметрии;
- backend/API и база данных;
- авторизация, пользователи и роли;
- административная панель;
- загрузка, изменение и удаление файлов из интерфейса;
- push-уведомления и аварийная диспетчеризация;
- история показателей и графики;
- журналирование действий;
- серверное версионирование документов;
- гарантированное офлайн-распознавание речи;
- публикация в Google Play;
- поддержка iOS как отдельное требование;
- редактирование DOC/DOCX/XLS/XLSX;
- гарантированные показатели точности распознавания речи и намерений.

## 4. Навигация и общий интерфейс

В нижней части экрана размещается фиксированное меню из трёх разделов:

1. **Голос**
2. **Телеметрия**
3. **Документы**

Разделы «Схемы» и «Библиотека» из исходного макета объединяются в раздел «Документы».

Интерфейс должен визуально соответствовать предоставленному референсу:

- светлый фон;
- тёмно-бирюзовый основной цвет;
- карточки со скруглениями;
- зелёная, жёлтая, оранжевая и красная индикация статусов;
- крупные значения метрик;
- элементы управления, пригодные для мобильного экрана;
- системные состояния загрузки, отсутствия данных и ошибки.

Точное пиксельное копирование макета не требуется. Макет задаёт стиль и состав основных экранов.

## 5. Текущий объект

Приложение хранит понятие текущего объекта в состоянии интерфейса.

Текущий объект меняется при:

- выборе в разделе «Телеметрия»;
- выборе в разделе «Документы»;
- успешном поисковом или голосовом запросе с явным названием объекта.

Последний выбранный объект сохраняется в `localStorage` и восстанавливается при повторном открытии приложения. Если сохранённый объект удалён из конфигурации, выбирается первый доступный объект.

Контекстные команды без названия объекта, например «Покажи схему этого объекта», относятся к текущему объекту.

## 6. Раздел «Голос»

### 6.1. Элементы экрана

- индикатор состояния;
- крупная кнопка микрофона;
- поле распознанной или введённой фразы;
- кнопка выполнения текстового запроса;
- карточка результата;
- кнопка повторного озвучивания ответа;
- набор кнопок с примерами демо-команд.

### 6.2. Состояния

- «Нажмите, чтобы задать вопрос»;
- «Слушаю…»;
- «Распознаю…»;
- «Ищу…»;
- «Говорю…»;
- «Распознавание речи недоступно — введите запрос текстом»;
- «Ничего не найдено»;
- «Ошибка доступа к микрофону».

### 6.3. Распознавание речи

При наличии `SpeechRecognition` или `webkitSpeechRecognition` приложение:

1. запрашивает разрешение на использование микрофона только после нажатия пользователя;
2. запускает распознавание с языком `ru-RU`;
3. помещает распознанный текст в поле запроса;
4. передаёт текст локальному обработчику команд;
5. показывает и при возможности озвучивает результат.

Распознавание через браузер считается экспериментальной функцией. Оно может зависеть от версии браузера, устройства, наличия интернета и внешнего сервиса распознавания.

Если распознавание не поддерживается, приложение не должно показывать неработающую кнопку как доступную функцию. Пользователю предлагаются текстовый ввод и демо-команды.

### 6.4. Поддерживаемые намерения

Локальный обработчик должен распознавать ограниченный набор намерений:

- показать объект;
- получить значение метрики;
- показать общую ситуацию по объекту;
- открыть схему;
- открыть режимную карту;
- открыть документы объекта;
- обновить данные из JSON без полной перезагрузки страницы.

Поиск выполняется без LLM и внешнего NLP-сервиса: нормализация регистра и знаков препинания, поиск ключевых слов, названий и псевдонимов из конфигурации.

### 6.5. Демо-команды

Минимальный набор:

- «Какое давление на входе ГРП-2?»
- «Какое давление на выходе этого объекта?»
- «Покажи температуру в помещении»;
- «Какая ситуация по ГРП-2?»
- «Покажи схему этого объекта»;
- «Открой режимную карту ГРП-2»;
- «Открой документы по этому объекту»;
- «Обнови данные».

Конкретные команды могут быть заданы в общей JSON-конфигурации. Нажатие на демо-команду должно давать тот же результат, что и ввод соответствующего текста.

### 6.6. Озвучивание

Для озвучивания используется `window.speechSynthesis` с русским голосом, если он доступен. При отсутствии подходящего голоса результат только отображается текстом.

## 7. Раздел «Телеметрия»

### 7.1. Элементы экрана

- выпадающий выбор объекта;
- тип, название и адрес объекта;
- дата и время ручного обновления данных;
- общий статус объекта;
- карточки настроенных метрик;
- список состояния оборудования, если он заполнен в конфигурации;
- кнопка «Обновить»;
- кнопка «Схема объекта»;
- кнопка «Режимная карта»;
- кнопка «Документы объекта».

### 7.2. Метрики по умолчанию

- давление на входе;
- давление на выходе;
- перепад давления на фильтре;
- температура в помещении.

Состав метрик не зашивается в интерфейс жёстко. Каждая карточка создаётся из массива `metrics` в JSON, поэтому для объекта можно добавить, удалить или переименовать показатель без изменения исходного кода.

Для метрики поддерживаются:

- уникальный код;
- название;
- числовое или текстовое значение;
- единица измерения;
- статус;
- допустимый диапазон;
- время обновления;
- иконка из предусмотренного приложением набора;
- поисковые псевдонимы.

Кнопка «Обновить» повторно загружает JSON-конфигурацию с сервера. Она не генерирует новые показания и не обращается к реальной телеметрии.

---

## 8. Статусы

Поддерживаются статусы:

| Код | Отображение | Цвет |
|---|---|---|
| `normal` | Норма | зелёный |
| `warning` | Предупреждение | жёлтый |
| `deviation` | Отклонение | оранжевый |
| `alarm` | Авария | красный |
| `unknown` | Нет данных | серый |

Статус задаётся вручную в JSON. Приложение не обязано вычислять его по допустимому диапазону. Если статус объекта не задан, он вычисляется как наиболее серьёзный из статусов его метрик.

## 9. Раздел «Документы»

### 9.1. Возможности

- выбор объекта;
- просмотр всех документов текущего объекта;
- фильтрация по категории;
- поиск по названию документа;
- отображение названия, типа, даты и размера, если они заданы;
- открытие документа;
- быстрое открытие основной схемы;
- быстрое открытие основной режимной карты.

### 9.2. Категории

- схемы;
- режимные карты;
- паспорта;
- акты;
- инструкции;
- прочее.

### 9.3. Форматы

Встроенный просмотр обязателен для:

- JPG/JPEG;
- PNG;
- WebP;
- PDF средствами браузера.

Другие файлы допускается открывать или скачивать обычной ссылкой без гарантии встроенного просмотра.

Документы физически размещаются в публичном каталоге сайта. URL каждого документа задаётся в конфигурации объекта. Приложение не сканирует каталог и не формирует список файлов автоматически.

### 9.4. Основные документы

В конфигурации можно отметить по одному документу как:

- основная схема объекта;
- основная режимная карта объекта.

Если документ отсутствует, соответствующая кнопка блокируется либо выводится сообщение «Документ для данного объекта не добавлен».

## 10. Конфигурация данных

Для демонстрационной версии используется JSON. YAML не применяется, чтобы не подключать дополнительный парсер и не создавать два равноправных формата.

### 10.1. Структура каталогов

```text
public/
  config/
    app.json
    objects.json
    objects/
      grp-2.json
      shrp-5.json
  documents/
    grp-2/
      scheme.pdf
      regime-card.pdf
    shrp-5/
      scheme.jpg
  icons/
```

`objects.json` содержит краткий список объектов и путь к конфигурации каждого объекта. Отдельный JSON на объект упрощает ручное редактирование и добавление документов.

### 10.2. Общая конфигурация

Пример `objects.json`:

```json
{
  "objects": [
    {
      "id": "grp-2",
      "name": "ГРП-2",
      "type": "ГРП",
      "address": "ул. Промышленная, 14",
      "aliases": ["второй грп", "грп два", "грп на промышленной"],
      "configUrl": "/config/objects/grp-2.json"
    }
  ]
}
```

### 10.3. Конфигурация объекта

Пример `grp-2.json`:

### 10.4. Правила конфигурации

- `id` объектов и документов должны быть уникальными и стабильными;
- пути рекомендуется задавать от корня сайта;
- конфигурация хранится в UTF-8;
- неизвестные необязательные поля игнорируются;
- ошибка одного объекта не должна полностью блокировать приложение;
- при ошибке JSON показывается понятное сообщение с именем проблемного файла;
- в проекте должна быть команда проверки всех конфигурационных файлов перед публикацией;
- пример объекта и краткая инструкция по добавлению объекта входят в поставку.

## 11. PWA и офлайн-режим

Приложение должно содержать:

- `manifest.webmanifest`;
- иконки не менее 192×192 и 512×512;
- `name`, `short_name`, `start_url`, `display: standalone`, цвета темы и фона;
- зарегистрированный Service Worker;
- экран или сообщение об отсутствии сети.

Кэшируются:

- HTML, CSS, JavaScript и иконки приложения;
- последняя успешно загруженная конфигурация;
- документы, которые пользователь уже открыл, если их размер допускает кэширование.

При отсутствии сети приложение показывает последние доступные данные с явной отметкой:

> Нет соединения. Показаны демонстрационные данные, сохранённые ранее.

Голосовое распознавание в офлайн-режиме не гарантируется.

После публикации новой версии приложение должно корректно обновлять свой программный кэш. JSON-конфигурации и Service Worker не должны получать длительный HTTP-кэш на стороне nginx.

## 12. Обработка ошибок

| Ситуация | Поведение |
|---|---|
| Не загружен список объектов | Экран ошибки с кнопкой повтора |
| Повреждён JSON одного объекта | Сообщение об ошибке объекта, остальные объекты доступны |
| Нет объектов | Информационный экран «Объекты не настроены» |
| Не найден документ | Сообщение «Документ не найден» |
| Браузер не показывает PDF | Открыть PDF в новой вкладке или предложить скачать |
| Нет поддержки распознавания | Текстовый ввод и демо-команды |
| Запрещён микрофон | Инструкция разрешить микрофон в настройках сайта |
| Команда неоднозначна | Показать найденные варианты объектов или метрик |
| Команда не распознана | Показать примеры поддерживаемых вопросов |
| Нет сети | Показать ранее сохранённые данные |

## 13. Требования к nginx

В поставку должен входить готовый конфигурационный файл nginx для домена `medvedzol.soil.by`.

Он должен обеспечивать:

- перенаправление HTTP на HTTPS;
- обслуживание собранной статики;
- fallback всех маршрутов SPA на `index.html`;
- правильные MIME-типы для manifest, JSON, PDF и изображений;
- запрет длительного кэширования JSON и Service Worker;
- длительное кэширование версионированных JS/CSS-ресурсов;
- gzip или brotli при наличии модуля;
- базовые безопасные HTTP-заголовки;
- доступ к документам только по существующим URL;
- журнал доступа и ошибок.

Пример целевой конфигурации:

```nginx
server {
    listen 80;
    listen [::]:80;
    server_name medvedzol.soil.by;

    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl;
    listen [::]:443 ssl;
    http2 on;
    server_name medvedzol.soil.by;

    root /var/www/medvedzol/current;
    index index.html;

    ssl_certificate /etc/letsencrypt/live/medvedzol.soil.by/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/medvedzol.soil.by/privkey.pem;

    add_header X-Content-Type-Options nosniff always;
    add_header Referrer-Policy strict-origin-when-cross-origin always;
    add_header X-Frame-Options SAMEORIGIN always;
    add_header Permissions-Policy "camera=(), geolocation=()" always;

    location = /service-worker.js {
        try_files $uri =404;
        add_header Cache-Control "no-cache, no-store, must-revalidate" always;
    }

    location ~* ^/config/.*\.json$ {
        try_files $uri =404;
        add_header Cache-Control "no-cache, must-revalidate" always;
    }

    location /assets/ {
        try_files $uri =404;
        add_header Cache-Control "public, max-age=31536000, immutable" always;
    }

    location /documents/ {
        try_files $uri =404;
        add_header X-Content-Type-Options nosniff always;
    }

    location / {
        try_files $uri $uri/ /index.html;
        add_header Cache-Control "no-cache" always;
    }

    access_log /var/log/nginx/medvedzol.access.log;
    error_log /var/log/nginx/medvedzol.error.log;
}
```

Пути к каталогу сборки и сертификатам уточняются при развёртывании. Конфигурация должна быть проверена командой `nginx -t` до перезагрузки nginx.

## 15. Приёмочные критерии

Демонстрационная версия считается принятой, если:

1. `https://medvedzol.soil.by` открывается без предупреждения о сертификате.
2. Приложение корректно работает в актуальном Chrome на согласованном Android-устройстве.
3. PWA можно установить на главный экран, после чего она открывается без адресной строки в standalone-режиме.
4. Нижнее меню содержит три раздела и корректно переключает их.
5. Объекты загружаются из JSON, а добавление нового объекта не требует изменения исходного кода.
6. Метрики, значения, единицы и статусы отображаются из конфигурации.
7. Кнопка «Обновить» подхватывает опубликованные изменения JSON.
8. Для каждого настроенного объекта открываются его основная схема и режимная карта.
9. Поиск документов по названию и фильтрация по категории работают.
10. Текстовые демо-команды находят объект, метрику или документ.
11. На согласованном тестовом Android/Chrome выполняется попытка реального голосового распознавания.
12. При недоступном голосовом API все команды доступны через текст и демонстрационные кнопки.
13. При наличии русского TTS найденный ответ озвучивается.
14. После первой успешной загрузки оболочка приложения и последние данные доступны без сети.
15. Ошибка одного JSON-файла отображается пользователю и не ломает всё приложение.
16. Production-сборка выполняется по инструкции без ручного изменения исходного кода.
17. Предоставленный nginx-конфиг проходит `nginx -t` после подстановки фактических путей сертификатов и каталога сайта.

## 16. Допущения и ограничения

- Все отображаемые значения вводятся вручную и могут не соответствовать реальному состоянию оборудования.
- На интерфейсе должна присутствовать ненавязчивая отметка «Демонстрационная версия».
- Приложение не должно использоваться как источник аварийной или технологической информации.
- Качество распознавания названий ГРП/ШРП зависит от браузерного сервиса и акустических условий.
- Web Speech API поддерживается не всеми браузерами; обязательным считается текстовый сценарий.
- Публичный каталог документов означает, что любой человек, знающий URL, потенциально может получить файл. В демо-версию нельзя помещать конфиденциальные документы.
- Для закрытых или производственных данных потребуется отдельный backend с авторизацией.
- Изменение JSON на сервере является способом администрирования демонстрационной версии.
