# Обновлённое техническое задание  
## Голосовое приложение для работы с телеметрией и документами ШРП/ГРП 🎙️

---

## 1. Назначение приложения

Разработать мобильное приложение для Android, которое позволяет пользователю голосом и через интерфейс:

- получать данные телеметрии по объектам **ШРП, ГРП, ГРПШ**;
- прослушивать ответ голосом;
- просматривать текущие параметры объекта;
- открывать схемы и документы оборудования;
- загружать и хранить документы в библиотеке;
- получать аварийные уведомления;
- работать с объектами в полевых условиях.

---

## 2. Основные параметры телеметрии

Приложение должно отображать и озвучивать:

| Параметр | Единица |
|---|---|
| Давление на входе | МПа / кПа |
| Давление на выходе | МПа / кПа |
| Перепад давления на фильтре | кПа |
| Температура в помещении | °C |

Для каждого параметра отображается:

- текущее значение;
- единица измерения;
- статус;
- время последнего обновления;
- допустимый диапазон;
- источник данных.

---

## 3. Структура приложения и навигация

Нижнее меню приложения должно содержать **3 основных раздела**:

1. **Голос**
2. **Телеметрия**
3. **Документы**

Разделы **«Схемы»** и **«Библиотека»** объединяются в один раздел **«Документы»**.

---

## 4. Раздел «Голос» 🎙️

Раздел предназначен для голосового управления приложением.

### Основные функции

- запуск голосового запроса;
- отображение распознанной фразы;
- анализ запроса;
- выполнение действия;
- озвучивание результата;
- отображение карточки результата.

### Состояния экрана

- **Слушаю…**
- **Распознаю…**
- **Обрабатываю запрос…**
- **Получаю данные…**
- **Говорю…**
- **Ошибка**

### Примеры голосовых запросов

Пользователь может говорить не только точные команды, но и естественные фразы:

- «Какое давление на входе ГРП-2?»
- «Скажи входное давление по второму ГРП»
- «Что сейчас на выходе?»
- «Покажи температуру в помещении»
- «Открой схему этого объекта»
- «Покажи паспорт фильтра»
- «Какая ситуация по ГРП на Промышленной?»
- «Обнови данные»
- «Открой документы по этому объекту»

## 5. Требования к NLP и голосовому управлению

Приложение должно поддерживать обработку естественного языка на русском языке.

### NLP должен определять:

| Сущность | Пример |
|---|---|
| Намерение пользователя | получить телеметрию, открыть документ, обновить данные |
| Объект | ГРП-2, ШРП-5, объект на Промышленной |
| Параметр | давление на входе, давление на выходе, температура |
| Тип документа | схема, паспорт, акт, инструкция |
| Оборудование | фильтр, регулятор, датчик давления |

## 6. Контекст диалога и текущий объект

В приложении вводится понятие **«текущий объект»**.

### Текущий объект определяется:

- выбором пользователя в разделе «Телеметрия»;
- последним объектом, по которому был голосовой запрос;
- объектом, открытым в карточке телеметрии;
- объектом, связанным с открытым документом.

### Пример контекстного диалога

Пользователь:

> «Покажи ГРП-2»

Приложение открывает телеметрию ГРП-2.

Пользователь:

> «А какое давление на выходе?»

Приложение понимает, что речь идёт про **ГРП-2**, и отвечает:

> «Давление на выходе ГРП-2 составляет 0,28 мегапаскаля.»

## 7. Требования к точности голосового управления

Минимальные требования:

- успешное распознавание типовых команд — **не менее 90%**;
- успешное определение намерения пользователя — **не менее 85%**;
- корректное определение объекта при явном названии — **не менее 90%**;
- корректная работа с контекстом — **не менее 85%**.

Если команда распознана неуверенно, приложение должно уточнить запрос.

Пример:

> «Вы имели в виду ГРП-2 или ГРП-3?»

## 10. Быстрый просмотр схемы из телеметрии

В карточке телеметрии объекта должна быть возможность быстро открыть схему.

### Требования

На экране телеметрии должна быть кнопка:

> **«Схема объекта»**

При нажатии:

- открывается основная схема объекта;
- если схем несколько — показывается список;
- если схемы нет — выводится сообщение:

> «Схема для данного объекта не загружена.»

Также схема должна открываться по голосовой команде:

> «Покажи схему этого объекта»

### Требования

- заменить текущую версию;
- создать новую версию;

### Пример

## 16. Получение телеметрии

Для получения телеметрии допускается два варианта.

### Вариант 1. REST + polling

Используется, если данные телеметрии обновляются не чаще 1 раза в несколько секунд или минут.

Приложение периодически запрашивает данные:

- при открытии карточки объекта;
- по кнопке **«Обновить»**;
- по голосовой команде;
- автоматически с заданным интервалом.

Рекомендуемый интервал polling:

- стандартно — **30 секунд**;
- при активном просмотре объекта — **5–10 секунд**;
- в фоне — по необходимости или отключено.

### Вариант 2. WebSocket

Используется, если требуется отображение данных почти в реальном времени.

WebSocket рекомендуется для:

- аварийных состояний;
- диспетчерского режима;
- частого обновления параметров;
- отображения динамики.

### Рекомендуемое решение

Для базовой версии использовать:

- **REST + polling** для обычной телеметрии;
- **push-уведомления / серверные события** для аварий.

WebSocket предусмотреть как расширение, если система телеметрии поддерживает потоковую передачу данных.

## 17. Аварийные уведомления ⚠️

Аварийные уведомления должны приходить пользователю при выходе параметров за допустимые пределы.

### Каналы уведомлений

- push-уведомления;
- уведомление внутри приложения;
- звуковой сигнал;
- визуальное выделение красным цветом.

### Источник уведомлений

Аварийные события должны формироваться на backend или в системе телеметрии и передаваться в приложение.

### Уведомление должно содержать:

- объект;
- параметр;
- текущее значение;
- допустимый диапазон;
- статус;
- время события;
- рекомендацию.

### Пример

> ⚠️ Авария на ГРП-2  
> Давление на выходе: 0,05 МПа  
> Допустимый диапазон: 0,20–0,30 МПа  
> Рекомендуется проверить регулятор давления.

## 22. Обработка ошибок и fallback-сценарии

Приложение должно корректно обрабатывать ошибки.

### Возможные ситуации

| Ситуация | Поведение приложения |
|---|---|
| Не распознана команда | Попросить повторить запрос |
| Не найден объект | Предложить выбрать объект из списка |
| Не найден параметр | Показать доступные параметры |
| Не найден документ | Предложить открыть раздел «Документы» |
| Нет связи с сервером | Показать кэшированные данные |
| Нет данных телеметрии | Показать дату последнего успешного обновления |
| Ошибка авторизации | Предложить повторный вход |
| Низкая уверенность NLP | Задать уточняющий вопрос |

### Примеры fallback-фраз

> «Я не нашёл объект ГРП-2. Выберите объект из списка.»

> «Не удалось получить свежие данные. Показываю последние сохранённые значения.»

> «Я не уверен, какой документ открыть. Уточните: схема, паспорт или акт?»
